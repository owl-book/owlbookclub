# 🦉 부엉이들의서재

**동네책방 독서모임, 날짜별로 한눈에**

- 배포 URL: https://www.owlbookclub.com (예전 주소 https://owlbookclub.vercel.app 도 그대로 열림)
- GitHub: https://github.com/owl-book/owlbookclub

## 서비스 소개

| | |
|---|---|
| **문제** | 동네책방 독서모임 정보는 책방마다 인스타그램·블로그·네이버폼에 흩어져 있어서, "이번 주말에 갈 수 있는 모임"을 찾으려면 여러 곳을 일일이 뒤져야 합니다. |
| **해결** | 서울·경기 동네책방 모임을 한곳에 모아 날짜·지역·장르·모임 방식으로 걸러 보고, 마음에 드는 모임은 책방 신청 페이지로 바로 연결합니다. |
| **기대효과** | 독서모임에 처음 가 보려는 사람은 탐색 시간이 줄고, 작은 책방은 새 손님을 만날 수 있습니다. |

- **주요 타깃**: 독서모임에 관심은 있지만 어디서부터 찾아야 할지 모르는 20~40대 직장인·대학생
- **핵심 행동(CTA)**: 모임 카드에서 **「책방에서 신청하기」** 버튼을 눌러 책방 신청 페이지로 이동
- 신청·결제는 각 책방에서 합니다. 부엉이들의서재는 정보를 모으고 연결만 합니다.

## 기술 스택

- **Next.js 16** (App Router, 서버 컴포넌트, Server Actions) · **React 19** · **TypeScript**
- **Tailwind CSS v4**: 디자인 토큰(색·글꼴·라운드)을 `globals.css`의 `@theme`으로 정의
- **Supabase**: PostgreSQL(데이터) + Storage(책 표지·전시 포스터 사진)
- **Vercel**: 배포
- 글꼴: Pretendard(본문), Cafe24 아네모네(제목)

## 미션 8 고도화 기능: 유저 기능 (간편 로그인 + 마이페이지)

### 왜 유저 기능을 골랐나

| | |
|---|---|
| **MVP의 한계** | 미션 6·7의 MVP는 "모임을 찾아서 책방 신청 페이지로 보내는 것"에서 끝났습니다. 사용자가 누구인지 모르니 마음에 든 모임을 저장해 둘 수 없고, 신청했는지·다녀왔는지도 남지 않아서 **다시 돌아올 이유**가 없었습니다. |
| **보완하려는 것** | 로그인한 사용자에게 "내 것"을 남길 자리를 만들어서, 한 번 찾고 끝나는 서비스가 아니라 **다시 열어 보는 서비스**로 바꿉니다. |
| **다른 선택지를 고르지 않은 이유** | 결제는 각 책방이 직접 받고 있어서 지금 서비스가 끼어들 이유가 없습니다. OpenAI 기능(예: 모임 추천)은 사용자 기록이 쌓여야 의미가 있어서, 그 기록을 모을 유저 기능이 먼저입니다. |

### 이번에 만든 최소 범위

"있으면 좋은 기능"은 빼고, 다시 돌아오게 만드는 데 꼭 필요한 것만 만들었습니다.

| 꼭 필요한 기능 | 내용 |
|---|---|
| 간편 로그인 | 카카오·구글(네이버는 검수 중, 아래 참고). 가입 양식 없이 버튼 하나로 시작 |
| 찜하기 | 모임·책방·전시에 하트. 로그인 전에 눌러도 로그인 뒤 그대로 저장 |
| 내 모임 | 신청했어요 / 다녀왔어요 표시, 다녀온 모임에 기록(별점·문장·메모) |
| 내 정보 | 별명 바꾸기, 로그아웃, 다른 기기 모두 로그아웃, 탈퇴 |

일부러 하지 않은 것: 이메일·전화번호 받기, 아이디·비밀번호 가입, 프로필 사진, 다른 사람과 기록 공유.

### 기존 서비스 흐름 안에서의 위치

로그인은 **처음부터 요구하지 않습니다.** 모임 찾기·상세 보기·책방 신청 페이지 이동은 지금처럼 로그인 없이 됩니다. "저장하고 싶을 때"에만 로그인을 묻습니다.

```
홈(모임 목록) → 모임 상세 → ♡ 찜 누르기
                              │ 로그인 안 했으면
                              ▼
                     로그인 화면(카카오·구글)
                              │ 처음이면 별명 정하기(/welcome)
                              ▼
                 원래 보던 모임 상세로 돌아옴 + 찜 저장 완료
                              ▼
   책방에서 신청하기 → (모임 뒤) 마이페이지 「내 모임」→ 다녀왔어요 → 기록 쓰기
```

| 언제 쓰나 | 무엇을 입력하나 | 어떤 결과를 얻나 |
|---|---|---|
| 마음에 드는 모임·책방을 나중에 다시 보고 싶을 때 | 하트 누르기 (로그인 안 했으면 카카오·구글 버튼) | 마이페이지 찜 탭에 모아 보기. 로그인 전에 누른 하트도 로그인 뒤 저장됨 |
| 책방에서 신청을 마쳤을 때 | 「신청했어요」 표시 | 「내 모임」에 일정으로 모임 |
| 모임에 다녀온 뒤 | 「다녀왔어요」 → 별점(1~5), 인상 깊은 문장, 메모 | 나만 보는 독서모임 기록이 쌓임 |
| 별명을 바꾸거나 그만 쓰고 싶을 때 | 별명 입력 / 탈퇴 확인 | 화면 이름 변경 / 회원 정보·찜·기록 모두 삭제 |

### 데모 시나리오 (따라 해 보기)

1. https://www.owlbookclub.com 에서 아무 모임 카드를 눌러 상세 화면으로 갑니다.
2. 하트를 누르면 로그인 화면이 열립니다. 「카카오로 시작하기」 또는 「구글로 시작하기」를 누릅니다.
3. 처음이면 별명을 정하는 화면이 나오고, 그다음 **보던 모임 상세로 돌아오며 하트가 켜져 있습니다.**
4. 오른쪽 위 마이페이지(`/me`)에서 찜한 모임을 확인합니다.
5. 모임 상세에서 「신청했어요」를 누르면 마이페이지 「내 모임」(`/me?tab=mine`)에 나타납니다.
6. 이미 지난 모임이면 「다녀왔어요」 → 「기록 쓰기」로 별점·문장·메모를 저장하고, 다시 열어 고치거나 지웁니다.
7. 내 정보(`/me/account`)에서 별명 바꾸기·로그아웃·탈퇴를 해 봅니다.

실패 경우도 확인할 수 있습니다.
- 로그인 화면에서 카카오·구글 동의를 **취소** → "로그인을 취소했어요." 안내
- 로그인 안 한 채 `/me`, `/me/records/1` 주소로 바로 들어가기 → 로그인 화면으로 이동, 로그인하면 그 화면으로 돌아옴
- 없는 로그인 방법 주소(`/auth/facebook`) → "지금은 이 로그인 방법을 쓸 수 없어요." 안내
- 다른 기기에서 탈퇴하거나 「다른 기기 모두 로그아웃」을 누른 뒤 이 기기에서 저장 → "로그인이 풀렸어요. 다시 로그인하면 이어서 저장할 수 있어요." 안내

### 기술 선택 이유

| 선택 | 이유 | MVP 단계의 장점 | 단점·감수한 점 |
|---|---|---|---|
| **OAuth 2.0 간편 로그인을 직접 연결** (`src/lib/oauth.ts`) | 카카오·네이버·구글 세 곳 모두 같은 "인가 코드" 방식이라 코드 한 벌로 처리 가능. 국내 사용자는 카카오 로그인이 가장 익숙함 | 외부 인증 서비스·라이브러리 없이 파일 몇 개로 끝남. 어떤 정보를 받는지 코드에서 바로 보임 | 로그인 회사를 늘릴 때마다 설정을 직접 추가해야 함. 같은 사람이 카카오·구글로 각각 들어오면 다른 회원이 됨 |
| **서명한 쿠키로 로그인 유지** (`src/lib/auth-shared.ts`, HMAC-SHA256) | 로그인 상태를 DB 세션 표 없이 쿠키 하나에 담고, `AUTH_SECRET`으로 서명해 위조를 막음 | 화면마다 DB를 읽지 않아 빠름. 구조가 단순함 | 쿠키만으로는 즉시 끊을 수 없어서, 저장 직전·마이페이지에서는 DB의 "출입증 버전"(`session_version`)을 한 번 더 확인함 |
| **회원 고유번호·별명만 받기** | 이메일·전화번호는 지금 쓸 곳이 없음 | 개인정보 부담이 적고, 동의 항목이 적어 로그인 이탈이 줄어듦 | 나중에 이메일 알림을 하려면 선택 동의를 따로 받아야 함 |
| **Supabase Auth를 쓰지 않음** | 이미 DB 접근을 서버(service role)에서만 하도록 만들어 둠(RLS 켜고 정책 없음) | 기존 구조를 바꾸지 않고 `users` 표 하나만 추가 | 비밀번호 찾기·이메일 인증 같은 기능은 직접 만들어야 함(지금은 필요 없음) |

### 기존 MVP와의 통합

- 로그인하지 않아도 모임 목록·상세·책방 신청 이동은 그대로 됩니다(기존 흐름을 막지 않음).
- 관리자 로그인(`ADMIN_PASSWORD`)과 회원 로그인은 서로 다른 쿠키라 섞이지 않습니다.
- 로그인 키가 하나도 설정되지 않은 환경에서는 로그인 기능이 꺼지고, 나머지 화면은 그대로 동작합니다(`isAuthEnabled()`).
- 기존 이용 기록(`events`)에 `user_id` 칸만 더해 로그인 이용자 수를 셀 수 있게 했습니다.

### 보안·입력값 확인

- 로그인 열쇠(`*_CLIENT_SECRET`, `AUTH_SECRET`)는 환경 변수로만 두고 서버에서만 읽습니다. 브라우저 코드에는 `NEXT_PUBLIC_`으로 시작하는 공개 값만 들어갑니다.
- 로그인 쿠키는 `httpOnly`(자바스크립트로 못 읽음), `secure`(https만), `sameSite=lax`.
- 로그인 시작 때 위조 방지값(`state`)을 만들어 10분짜리 서명 쿠키에 담고, 돌아올 때 같은지 확인합니다. 다르면 "로그인 시간이 지났어요"로 처리합니다.
- 로그인 뒤 돌아갈 주소(`next`)는 우리 사이트 안의 주소만 허용합니다(`safeNext`, 외부 사이트로 튕기기 방지).
- 찜·기록·탈퇴 등 모든 저장 동작은 맨 앞에서 로그인 본인인지 다시 확인하고, DB 조회에는 항상 `user_id = 본인` 조건을 붙입니다. 다른 사람 기록 번호를 넣어도 내 기록만 보입니다.
- 별점은 1~5, 문장 500자, 메모 5000자를 서버와 DB 제약조건 양쪽에서 확인하고, 별명 길이·주소의 번호(숫자인지)는 서버에서 확인합니다.
- 탈퇴하면 회원 행을 지우고 찜·기록은 함께 삭제됩니다(외래 키 `on delete cascade`). 카카오는 연결 끊기까지 합니다.

### UX: 로딩·오류·빈 상태

| 상황 | 사용자에게 보이는 것 |
|---|---|
| 마이페이지·기록 화면을 불러오는 중 | 뼈대 화면(`src/app/me/**/loading.tsx`) |
| 저장 버튼을 누른 뒤 처리 중 | 버튼이 잠기고 "저장하는 중…" |

| 로그인이 풀렸는데 저장하려 함 | "로그인이 풀렸어요" 안내 후 다시 로그인하면 하던 일로 돌아옴 |
| 찜·내 모임이 비어 있음 | "찜한 책방이 없어요 — 책방 이름 옆 하트를 누르면 여기에 모여요"처럼 무엇을 하면 채워지는지 안내 |
| 마이페이지에서 예기치 못한 오류 | 오류 안내 화면(`src/app/me/error.tsx`) |
| 왜 로그인해야 하는지 | 로그인 화면에 "모임·책방 찜하기 / 신청한 일정 모아 보기 / 다녀온 모임 기록하기" 혜택 안내 |

### 확장 가능성

- **로그인 회사 추가**: `PROVIDERS`에 항목 하나만 더하면 됩니다. 네이버는 이미 들어 있고, 검수가 끝나면 새 주소에서 버튼을 다시 보이게 합니다(`isProviderShownOn`).
- **다른 고도화 기능과 연결**: 회원별 찜·신청·기록이 쌓이므로 이후 OpenAI 추천(내 기록 기반 모임 추천)이나 결제(회원별 결제 내역)를 같은 `users.id`에 붙일 수 있습니다. 실제로 PWA 알림(찜한 모임 마감 알림)을 이 회원 정보 위에 추가했습니다.
- **사용자 수 증가**: 로그인 확인은 쿠키 서명 검사라 화면을 볼 때마다 DB를 읽지 않습니다. 회원별 표에는 `user_id` 색인을 두었습니다.
- **막혀 있는 부분**: 같은 사람의 카카오·구글 계정을 하나로 합치는 기능은 아직 없습니다(필요해지면 계정 연결 표를 추가).

## 핵심 기능 명세

서비스의 핵심 가치("흩어진 모임 정보를 믿을 수 있게 한곳에")를 검증하는 CRUD 흐름 두 가지를 선정했습니다.

| | ① 모임 정보 관리 (운영자) | ② 내 참여 기록 (회원) |
|---|---|---|
| 검증하려는 것 | 정확한 모임 정보를 빠르게 올리고 고칠 수 있는가 | 다녀온 모임을 기록하러 다시 돌아오는가 |
| 데이터 | `meetings`, `stores`, `book_covers` + Storage | `meeting_records` |
| 처리 방식 | Server Actions (`src/lib/review-actions.ts`, `admin-actions.ts`, `cover-actions.ts`) | Server Actions (`src/lib/me-actions.ts`) |
| 접근 | 관리자 비밀번호(`ADMIN_PASSWORD`) | 간편 로그인(카카오·구글) 본인만 |

### ① 모임 정보 관리

일반적인 게시판과 달리, 모임은 운영자가 책방 공지를 보고 정리해서 올립니다. 잘못된 정보가 바로 공개되지 않도록 **"숨긴 채로 등록 → 승인 화면에서 확인·수정 → 공개"** 흐름을 씁니다. 공개된 모임은 지우지 않고 **숨기기**로 내립니다(찜·기록이 모임에 연결돼 있어서).

**사용자 흐름**: 승인 대기 목록 → 미리보기(상세) → 고치기 → 공개 / 넣지 않음 → 공개 목록·상세 → 신고 처리(마감·숨기기·일정 수정)

| 화면 | 주소 | 입력 / 사용자 행동 | 성공 결과 | 실패 결과 |
|---|---|---|---|---|
| **Create** 등록 | (운영 도구) | 모임 정보를 `pending_review = true`, `is_hidden = true`로 DB에 저장 | 승인 대기 목록에 나타남 | 필수값이 없으면 DB 제약조건으로 저장 거부 |
| **Read** 승인 대기 목록 | `/admin/review` | 책방별 대기 모임 확인 | 책방·모임 카드 목록 | 대기 없음 → 빈 상태 안내 |
| **Read** 미리보기(상세) | `/admin/review/[id]` | 카드에서 미리보기 누르기 | 공개 화면과 같은 상세 화면 | 없는 번호·이미 처리한 모임 → 없는 페이지 안내 |
| **Update** 고치기 | `/admin/review` 안 고치기 폼 | 제목, 일시, 끝나는 시각, 장르, 모임 방식, 신청 링크, 장소, 참가비, 소개 등 | 저장 후 "고쳤어요" 안내, 바뀐 값 표시 | 제목 빈칸·일시 형식 오류·끝나는 시각이 시작보다 빠름·링크 형식 오류 → 해당 칸 오류 안내 |
| **Update** 공개(승인) | `/admin/review` | 「공개하기」 | 홈 목록·상세에 바로 보임. 같은 묶음 회차·대기 중인 책방도 함께 공개 | 신청 링크가 비어 있으면 공개를 막고 "신청 링크가 비어 있어서 승인하지 않았어요" 안내 |
| **Delete** 넣지 않음 / 숨기기 | `/admin/review`, `/admin/reports` | 「넣지 않음」, 신고 처리 「숨기기」 | 목록·상세에서 사라짐(데이터는 보관, 변경 전·후 값을 `admin_actions`에 기록) | 이미 처리한 모임 → "화면을 새로 고쳐 주세요" |
| **파일** 책 표지 | `/admin/covers` | 표지 사진 고르기 → 올리기 / 빼기 | 모임 카드·상세에 표지 표시 | 사진 없음·1MB 초과·JPG/PNG/WEBP 아님 → 오류 안내. 표지가 없으면 디자인 표지로 대신 표시 |
| **Read** 공개 목록 | `/` | 날짜·지역·장르·모임 방식·검색어 | 날짜별 모임 카드 | 조건에 맞는 모임 없음 → 빈 상태 안내 |
| **Read** 공개 상세 | `/m/[id]` | 카드 누르기 | 모임 상세, 신청 버튼 | 없는 번호·숨긴 모임 → 없는 페이지 안내 |

### ② 내 참여 기록

다녀온 모임에 별점, 인상 깊은 문장, 메모를 남깁니다. 기록은 본인만 볼 수 있습니다.

**사용자 흐름**: 마이페이지 「내 모임」 목록 → 다녀왔어요 표시 → 기록 쓰기(등록) → 목록에서 다시 열기(상세) → 고치기 → 지우기

| 화면 | 주소 | 입력 / 사용자 행동 | 성공 결과 | 실패 결과 |
|---|---|---|---|---|
| **Read** 목록 | `/me?tab=mine` | 로그인 후 마이페이지 | 신청·다녀온 모임과 기록 여부 표시 | 로그인 안 함 → 로그인 화면. 모임 없음 → 빈 상태 안내 |
| **Create** 기록 쓰기 | `/me/records/[meetingId]` | 별점(1~5), 인상 깊은 문장(500자), 메모(5000자) | 저장 후 마이페이지로 돌아가 "기록을 저장했어요" 안내 | 아직 안 지난 모임 → 기록 불가. 글자 수 초과 → 입력 제한 |
| **Read** 기록 보기(상세) | `/me/records/[meetingId]` | 목록에서 기록 누르기 | 저장한 값이 채워진 화면 | 없는 모임 번호 → 없는 페이지 안내 |
| **Update** 고치기 | `/me/records/[meetingId]` | 값 바꾸고 저장 | `updated_at` 갱신, 목록에 반영 | 저장 실패 → 오류 안내 |
| **Delete** 지우기 | `/me/records/[meetingId]` | 「기록 지우기」 → 확인 창 | 확인하면 삭제, "기록을 지웠어요" 안내 | 확인 창에서 취소 → 그대로 유지 |

공통 처리
- 저장 버튼은 처리 중에 눌리지 않게 막고 버튼 문구를 "저장하는 중…"처럼 바꿔 보여 줍니다(`src/components/SubmitButton.tsx`).
- 되돌릴 수 없는 행동은 확인 창으로 한 번 더 묻습니다(`SubmitButton`의 `confirm`, `ConfirmSubmit.tsx`).
- 화면을 불러오는 동안 뼈대 화면(`loading.tsx`, `src/components/Skeleton.tsx`)을 보여 줍니다.
- 없는 주소는 안내 화면(`src/app/not-found.tsx`, `src/app/m/[id]`, `src/app/s/[id]/not-found.tsx`)으로 보냅니다.

| 칸 | 종류 | 필수 | 설명 |

### 그 밖의 표

`stores`(책방), `users`(회원), `meeting_wishes`·`store_wishes`(찜), `meeting_plans`(신청·참석 표시), `reports`(정보 오류 신고), `inquiries`(의견), `admin_actions`(운영자 변경 기록), `exhibitions`(책방 전시), `events`(이용 기록)

### 데이터 처리 규칙

- DB 접근은 서버에서만 합니다. 비밀 열쇠(`SUPABASE_SERVICE_ROLE_KEY`)는 브라우저로 보내지 않습니다.
- 모든 저장 동작은 맨 앞에서 관리자 또는 로그인 본인인지 다시 확인합니다. 기록의 읽기·쓰기·지우기에는 항상 `user_id = 본인` 조건을 붙입니다.
- 공개된 모임은 지우지 않고 숨깁니다. 운영자가 바꾼 내용은 `admin_actions`에 변경 전·후 값으로 남깁니다.
- 지난 모임 여부는 저장하지 않고 `starts_at`으로 그때그때 계산합니다.
- 지역·장르·모임 방식 목록은 앱 파일(`src/lib/regions.ts`, `src/lib/tags.ts`)과 DB 표를 함께 고칩니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env.local   # 값 채우기 (아래 환경 변수 참고)
npm run dev                  # http://localhost:3000
```

DB 표는 `supabase/migrations/`의 SQL을 번호 순서대로 Supabase SQL Editor에서 실행하고, 예시 데이터는 `supabase/seed_example.sql`로 넣습니다.

```bash
npm run build && npm start   # 배포용 빌드 확인
```
